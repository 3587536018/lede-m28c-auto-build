# 5G 模块 USB 槽位自适应

实机在 2026-10-16 的只读检查中，RM500Q-CN 留有 `4_1_2`、`3_1_2`、`2_1_2` 三个 QModem 配置段，对应 USB 路径 `4-1.2`、`3-1.2`、`2-1.2`；旧 AT 端口是 `ttyUSB3`，当前为 `ttyUSB2`。没有对在线设备重启、热拔插或修改配置。

锁定的 QModem 3.2.0 扫描器原本用 USB 槽位字符串生成 UCI 段名。总线编号改变会新建一段；原有 APN、拨号开关、别名、监控设置留在旧段。它会更新已找到设备的串口，但拨号与监控长进程也需要更新缓存的端口。

## 定制行为

首次成功扫描时，保存控制器的实际 sysfs 路径、完整 USB 物理端口链、根集线器 USB 协议、VID/PID 和模块型号。标识会排除 Linux 临时分配的 `usbN`、总线前缀及 `xhci-hcd.N.auto` 编号。无需预置设备序列号、IMEI、SIM 标识或固定 `ttyUSB` 编号。

之后在**同一物理接口、同一 USB 根协议**重新枚举时：

- 复用已登记的 UCI 配置段，保留 APN、拨号凭据、别名、路由优先级、拨号开关与监控设置。
- 刷新实际 USB 路径、验证过的 AT 端口、串口列表与网卡名；配置段名称保持稳定，使原有网络接口和监控引用可以继续使用。
- USB `devnum` 变化也视为重新连接，即使路径和串口名称相同，也重新启动对应拨号实例，避免继续使用失效的设备句柄。
- 断线监控每轮读取最新绑定。设备尚未出现、端口已属于别的设备，或等待期间发生重新枚举时，不执行针对旧设备的恢复动作。
- 拔出事件按当前路径定位配置段。旧总线的迟到事件不会停用已迁移到新路径的模块。
- 自动探测启动前先将旧 USB 记录标记为待探测，成功扫描后才恢复启用，防止启动期间按上一次开机的串口向其他模块拨号。手动关闭自动探测或固定设备配置保留其原有语义。
- 自动配置中已失效的 AT/SMS 端口覆盖会回退到本次验证过的自动端口，避免遗留手动串口编号越过重新识别结果。
- 开机启用 USB 全量扫描，继续使用上游的延迟扫描、热插拔事件与有限重试。

## 边界与升级

该机制解决固定物理口的 USB 总线和串口重编号。把模块移到其他物理口、改变 USB2/USB3 连接方式或更换不同 VID/PID/型号时，会独立识别，避免把其他模块的设置覆盖过来。它不会改变 SIM1/SIM2 的用户选择。

对升级前没有身份标记的旧配置，只在**当前路径和型号同时匹配**时登记。多个已失效的历史槽位不会根据型号自动合并；尤其不能从三份记录猜哪份 APN 或监控配置是用户希望保留的。完整公开新镜像没有这些历史记录，首次自行配置后即可登记并延续。手动设置 `fixed_device=1` 的设备继续遵循固定配置。

## 验证

本地回归使用实际 C 身份逻辑与模拟 UCI/sysfs/procd，覆盖总线变化、物理端口区分、历史配置、歧义、串口更新、USB 复位与迟到移除事件；另执行实际 shell 函数验证拨号实例替换及监控恢复判断。构建会核验补丁输入/输出哈希，并在开始交叉编译前对完整扫描器执行 C 语法检查。

这些测试不替代实机启动验收。固件完成并获准安装后，应在已配置拨号的情况下多次冷启动、单独复位模块，确认 UCI 段和 APN 保持不变、当前路径与端口更新、能够恢复联网；有第二个模块时还需验证设置互不混用。仅查看设备不包含刷机或重启授权。

## 已联网但状态为断开的补判

#103 实机发现 RM500Q-CN 使用 QMI/QMAP，netifd 的同模块数据接口已经 up、取得 IPv4/IPv6 地址并承载路由，`get_connect_status` 仍因 AT PDP 查询返回 `No`。补丁保留原 AT 判断；只有 AT 未确认连接时，才只读查询 netifd，要求接口 up 且存在非空、非未指定、非链路本地地址，并核对 `/sys/class/net/<l3_device>/device` 的真实路径确实位于当前 `modem_path` 下。QMAP 的额外 `/net/wwan0` 层次也支持。

其他 WAN 在线、失效设备、接口 down、仅链路本地地址、查询失败均不能令该模块变绿。此状态表示模块数据链路已建立，不承诺互联网端到端可达。修改只影响显示所用的连接查询，不重启拨号或改写网络配置。实机只读函数验证通过，完整页面在新固件上的显示仍需安装后确认。
