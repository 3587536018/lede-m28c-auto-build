# #103 实机反馈及恢复计划

2026-10-16 只读检查确认，设备已刷入 #103 的 squashfs 镜像。以下新修复进入下一次构建，不能把 #103 的验收报告当作修复后固件的验收。在线设备尚未应用这些文件。

## 自动挂载

镜像内 `/opt/docker` 是 Docker 软件包预置的空目录。旧初始化脚本把 `/opt` 里任何目录项都当成用户数据，因此创建 optdata 分区后停止挂载，随后启动的 Docker 把初始化文件写入系统 overlay。数据分区本身是 ext4，约 57 GiB；通过 SFTP 只读解析其文件系统，根目录只有空的 `lost+found`。检查时没有容器、镜像或卷。

新脚本允许 `/opt` 不存在、为空、仅含空的普通 `/opt/docker` 目录；在分区操作之前拒绝已有数据、其他目录、文件及链接。实际目录项检查不依赖 `ls` 输出内容，避免换行文件名被误认为空。已有文件系统不会重新格式化。

当前已启动设备的 `/opt/docker` 和 `/opt/containerd` 已不再为空，不能直接重跑新脚本隐藏它们。即时恢复的具体步骤如下，需用户确认后执行：

1. 再次核对当前启动分区、唯一 optdata 分区、挂载状态、可用空间及 Docker 容器/镜像/卷数量。确认分区仍为空且无新任务后继续；任何变化都先复核。
2. 备份 `/etc/config/fstab`、`/etc/config/dockerd`、原初始化脚本和当前 `/opt`，保留完整回退副本。
3. 短暂停止 Docker，确认其子进程及 `/opt` 下的子挂载已释放，将系统分区上的 `/opt` 原目录保存到独立备份目录；不删除原数据。
4. 安装修正后的初始化脚本，使用已经存在的 optdata ext4 分区挂载到 `/opt`，按 UUID 写入 fstab，创建 512 MiB swap。不得重新分区、格式化或覆盖已有分区内容。
5. 将备份中的 Docker/containerd 数据复制到新数据分区，再启动 Docker。确认 `/opt` 的真实设备、约 57 GiB 容量、Docker 数据根目录、swap 和服务状态。保留备份，出现错误时不删除任何一份数据。

这些操作不要求重刷固件或重启路由器，也不操作 5G 拨号。首次启动自动挂载仍需下一镜像的真实启动验收；模拟测试不能替代硬件测试。

## iStore 中文及软件源

iStore 主界面的中文 JSON 已工作，安装结果弹窗依赖 `lib-tasks.zh-cn.lmo`。上游 Makefile 把构建语言 `zh_Hans` 当成磁盘目录，而原始 PO 位于 `po/zh-cn`，导致 taskd 和 iStore 的简体中文 LMO 都漏编。已使用原始 PO 和官方 po2lmo 生成并检查截图中的三个词条。运行时继续使用 `luci.main.lang=zh_cn`。

即时修复可在备份后安装 `iStore.zh-cn.lmo`、`lib-tasks.zh-cn.lmo`，仅清理 LuCI 翻译/模板缓存并重新打开页面。原生翻译包不替换商店模板。

软件源修复可在备份当前 distfeeds 后，应用项目的五路已验签用户态补充源和官方 OpenWrt 24.10 公钥，再执行 `opkg update` 验证；保留 iStore compat 源。具体来源、签名与兼容边界见 `PACKAGE-FEEDS.md`。不执行整机批量软件升级。

## QModem 状态

实机同一模块的数据接口 up、有 IPv4/IPv6 地址并承载默认路由，但 `qmodem.get_connect_status` 返回 `No`。修复保留原 AT 查询结果，并在未连接时补查 netifd 数据接口与真实 sysfs 归属。已在设备内存中只读执行新判断，返回连接成功，未写入文件或调整拨号。

即时应用只需备份并替换核对过原始哈希的 `generic.sh` 状态查询代码，让下一次页面轮询使用新判断；不重启 QModem。接口连接状态并非互联网可达性探测。
