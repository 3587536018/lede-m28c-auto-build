# 系统 /opt 初始化策略

用户明确要求重刷后不保留旧 `/opt` 数据，并且不要 swap。新的
`files/etc/uci-defaults/99-expand-data` 按新安装执行一次系统数据分区初始化，
为 Docker 提供独立的 ext4 `/opt`。这与外置 USB/SD 的
[自动挂载](AUTOMOUNT.md) 是两个独立流程。

## 新安装与普通重启

新安装首次执行时，脚本识别实际启动盘和根分区，核验系统盘尾部的数据分区。
符合条件的旧数据分区会被重新格式化为 ext4，旧文件全部丢弃；尾部只有可用空闲
空间时，先创建数据分区再格式化。随后挂载到 `/opt`，写入按新 UUID 持久挂载的
fstab 配置，并把 Docker 数据目录设置为 `/opt/docker`。

初始化状态保存在当前安装可写层的 `/etc/m28c-opt-initialized`，镜像不预置该文件。
初始化成功后，OpenWrt 会删除已完成的 uci-defaults 脚本；后续普通重启由原生挂载
服务按 fstab 挂载 `/opt`，不会重新清空分区，之后创建的 Docker 容器、镜像和其他
文件会保留。清空配置重刷或恢复出厂会丢失安装状态，下一次初始化会再次丢弃
旧 `/opt` 数据；这正是本次要求的行为。

脚本不创建或启用 swap，新 fstab 的 `auto_swap`、`anon_swap` 均为 `0`；初始化器也
会将现有 global 配置的这两个选项设为 `0`。仅在 `fstab.swap.device` 正好是
`/opt/swapfile` 时清理该项目历史条目，不删除其他用户显式配置的 swap 条目。

## 分区核验与失败处理

格式化仅限识别出的系统盘第三分区。必须确认启动布局仍为 kernel 第一分区、
root 第二分区、数据第三分区，且数据区按 1 MiB 对齐紧随 root、至少 768 MiB；
内核识别的起点和大小还必须与分区表一致。正在使用的分区不能直接格式化：仅允许
把准确挂在 `/opt` 的候选分区正常卸载；Docker/containerd 运行、子挂载、活动 swap、
设备 holder、其他挂载或忙卸载均会阻止重置。系统启动和根分区、外置 USB/SD
盘，以及无法确定用途或存在冲突的分区不进入重置流程。无法证明目标安全时停止
初始化并记录错误，不凭标签或设备编号猜测后继续。

初始化以 `/var/lock/m28c-opt-init` 独占锁防止并发，并在格式化前持久保存 `pending`
检查点；格式化完成后保存包含新 UUID 的 `prepared` 检查点。挂载或 fstab 写入失败，
可以在 `prepared` 检查点和实际 ext4 文件系统一致时重试后续步骤，不重复格式化。
检查点损坏、分区变化、UUID 不一致或中断后无法确认格式化结果时，停止自动处理，
不会把异常状态当成一次全新的初始化。

Docker 启动前另有检查，确认实际 `/opt` 是独立的 ext4 数据挂载，且数据目录位于
其上。初始化或挂载失败时，Docker 不会将容器数据写进根文件系统 overlay；仅存在
`/opt` 目录或初始化标记不能代替真实挂载检查。

## 验证范围

隔离测试覆盖旧 ext4/exFAT 数据重置、尾部空闲空间创建、分区核验拒绝、检查点
失败与重试、普通重启不重复格式化，以及无 swap 的配置行为。测试使用临时目录
和模拟块设备命令，不格式化真实磁盘，也不连接在线路由器。

本文描述构建源码策略。实际新固件还须完成镜像下载、离线文件与包核验，再由用户
进行新安装与重启测试；不能据源码或隔离测试宣称已经在设备上验收完成。
